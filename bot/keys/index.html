TruloVenueBot — Key Directory

Public Ed25519 keys for verifying HTTP Message Signatures on TruloVenueBot requests.

Machine-readable directory

Verifiers should fetch the JSON directory and resolve keys by their kid:

  • https://trulo.dating/bot/keys/directory.json

The directory follows JWK-set conventions (RFC 7517) and lists every currently-valid public key. Verifiers should match a request's Signature-Input header keyid parameter against the kid field of an entry in the keys array.

Signature scheme

  • Algorithm: Ed25519 ("alg": "ed25519")
  • Wire format: HTTP Message Signatures (RFC 9421)
  • Components signed: @method, @target-uri, @authority, plus the standard signature parameters (created, keyid, alg)
  • Body: not signed — TruloVenueBot crawl traffic uses GET only
  • Header name: Signature (with the matching Signature-Input describing the covered components)

Key rotation

No fixed rotation schedule. Keys rotate on suspected compromise or operational change. When rotation does occur, we publish the new key alongside the existing one for a grace window so verifiers always have at least one valid key, then retire the old key once the grace window closes. kid values are opaque short strings; verifiers should not attempt to parse them.

Current status

The active signing key was published on 2026-05-04 and is listed in directory.json. Every TruloVenueBot request now carries RFC 9421 HTTP Message Signature headers (Signature-Agent, Signature-Input, Signature) referencing this key by kid. Verifiers can fetch this directory, match the request's keyid parameter against the kid field of an entry in the keys array, and verify the signature against the listed JWK.
