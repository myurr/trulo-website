TruloVenueBot

Trulo's venue-discovery crawler — public identity, policies, and contact channels.

What is TruloVenueBot?

TruloVenueBot is the crawler Trulo operates to discover publicly available information about UK venues — pubs, restaurants, cafés, cultural sites, parks, sport centres, and similar. The data powers venue discovery and date-planning features inside the Trulo app, and we link users back to the original venue sites rather than reproducing their content as our own.

The crawler is a clearly identified, policy-compliant aggregator. We do not bypass bot protections, authentication, paywalls, or CAPTCHAs. We respect robots.txt. We honour publisher opt-outs. If you operate a site we crawl and you'd prefer we didn't, jump to opt-out.

User-Agent string

Every request from TruloVenueBot announces itself with this exact User-Agent:

TruloVenueBot/1.0 (+https://trulo.dating/bot)

We never use a browser-style User-Agent on crawler traffic, and we never share this UA with the Trulo mobile app or any unrelated tooling. If you see this UA in your logs and the IP is not in our published list (below), it is not us.

IP address list

Every TruloVenueBot request egresses from one of the IP addresses published below. Site operators who prefer IP-based allow / deny rules can pin against this list.

The list is updated whenever our crawler infrastructure changes. We notify the major bot-management providers (Cloudflare, Akamai, DataDome, Fastly) of changes through their respective verified-bot channels.

Signed requests (Web Bot Auth)

TruloVenueBot signs every outbound request with HTTP Message Signatures (RFC 9421) using Ed25519. The active public key is published in the bot's key directory:

  • https://trulo.dating/bot/keys/ — human-readable
  • https://trulo.dating/bot/keys/directory.json — machine-readable JWK set

Every request carries Signature-Agent, Signature-Input, and Signature headers. The keyid parameter in Signature-Input matches the kid field of an entry in the directory's keys array; verifiers can fetch the directory and verify the signature against the listed JWK. Rotated keys are kept in the directory for a grace window before retirement.

robots.txt policy

  • We fetch each site's robots.txt before scheduling any crawl on that host, and re-check it weekly.
  • We honour User-agent: * and User-agent: TruloVenueBot directives. Either form works. Specific rules for our agent take precedence over wildcard rules per RFC 9309.
  • We honour Disallow and Allow.
  • We do not currently parse Crawl-delay; instead we apply a uniform 1-second minimum interval between requests to the same domain, which sits below the typical published Crawl-delay value. Native Crawl-delay support is on the roadmap.
  • If robots.txt returns 404 we treat the site as having no rules. If it returns 5xx or the fetch errors out, we currently fall back to allow on a fresh check, but we re-fetch on the next cycle. Tightening this to fail-closed on 5xx is on the roadmap.

Scope & exclusions

TruloVenueBot only fetches public venue pages and a small set of supporting pages:

  • Venue homepages and content pages (menus, opening hours, "about", contact)
  • Linked PDF menus and similar public assets
  • Schema.org / JSON-LD data embedded in venue pages
  • Images that the venue's own pages link to, for use as the venue's photo on Trulo

We never fetch:

  • Authenticated, account, login, or session-bound pages
  • Checkout, payment, basket, or reservation-flow pages
  • Admin dashboards or staff-only pages
  • Direct competitor pricing endpoints, scraping for resale, or bulk content extraction
  • Anything behind a CAPTCHA or bot challenge — if we hit one, we back off and stop

Rate-limiting philosophy

  • Per-host serialisation: a 1-second minimum between requests to the same domain, enforced regardless of crawl concurrency.
  • Per-host request rate is capped well below typical organic traffic. We do not bulk-extract.
  • Domains that error or time out are placed on an exponential backoff ladder (1 day → 2 days → 14 days → 28 days → permanently retired) and re-tried at decreasing frequency until they recover.
  • Cloudflare / Akamai / DataDome challenge pages are tagged as such on receipt; we do not retry challenge-tagged pages until our verified-bot status with the relevant provider is established.
  • We do not retry aggressively. We cap retries on transient errors and never bulk-replay.

Publisher opt-out & takedown

If you'd like TruloVenueBot to stop crawling your site, you have three options:

  1. robots.txt — add a Disallow rule for TruloVenueBot (or for *). We honour it on the next crawl cycle for that host, typically within 24 hours.
  2. Email — write to bot@trulo.dating with the domain you'd like removed. We action these within two working days and confirm by reply.
  3. Removal of already-collected data — the same email address handles takedown requests for any data we've already stored about your venue.

Abuse reporting

If TruloVenueBot is misbehaving — excessive load, ignored rules, content scraped beyond scope, or anything else that looks wrong — please report it to bot@trulo.dating. Include any log lines you have. We respond within one working day for active issues.
